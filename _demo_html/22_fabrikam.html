Audience Compliance & Governance / Risk / Internal Audit Format Demo + Guided hands-on Duration ~2 hours Tool Microsoft 365 Copilot

About this workshop

A practical, senior-practitioner-level immersion designed specifically for Fabrikam Healthcare’s risk and audit community. We move from strategic context → live demos → guided hands-on exercises covering every major M365 Copilot surface.

What you will leave with

  • Experience drafting a complete internal audit report from source evidence in Word, grounded on your audit charter, regulatory framework, and prior-year findings — with Copilot citing every source.
  • A risk register analysis and 5×5 heatmap built with Copilot in Excel, surfacing above-appetite risks and cross-referencing control failures against the incident log.
  • An Audit Committee presentation generated directly from your Word audit report using PowerPoint Copilot, with CFO-order storyline and speaker notes.
  • Hands-on practice triaging a complex incident email thread in Outlook and extracting structured action items from a Risk Committee meeting in Teams.
  • Your own tailored Copilot Agent for risk management and internal audit — deployed and shared with your team before you leave the room.

What this workshop is not

  • It is not a feature walkthrough — every tool is demonstrated in a Fabrikam risk and audit context, using realistic scenarios and documents.
  • It is not a replacement for professional judgment or IIA standards — Copilot drafts, you review and decide. Internal audit opinion remains yours.
  • It is not connected to live Fabrikam systems today — all data used is sample / illustrative only. Do not use workshop outputs for operational decisions.

Cowork is a multi-step agentic mode where you describe an outcome — and Copilot writes a plan, then executes across Word, Excel, PowerPoint, Outlook, Teams, and the browser. Perfect for the “last mile” of an audit engagement.

What Cowork produces in this exercise

  • 🌐 HTML — Copilot Page shared to the Risk & Audit Team channel
  • 📧 Email — sign-off request to CFO, CIO, and DPO
  • 📅 Meeting — Audit Committee readout scheduled in Outlook with Teams link
Prerequisites: Complete Exercises 1–4 first so the Word report, Excel results, and PowerPoint deck are already saved in OneDrive.

Exercise 10 · Copilot Analyst · Standardize & Consolidate20 min · Analyst agent · Different schemas → one Group risk register

When to do this: Open copilot.microsoft.com. In the mode selector, choose Analyst. Attach all 5 files from the Subsidiary Risk Registers folder before you start.

Every year, Group Risk faces the same headache: four subsidiaries each send their risk register in a different format, with different rating scales, different category names, and different levels of completeness. In this exercise, Analyst does the reconciliation for you — standardize the schemas, map every risk to the Group enterprise taxonomy, and flag exceptions in one pass.

The 5 files you need (all in the Subsidiary Risk Registers folder)

  • 🏥 KL_Hospital_Risk_Register_FY26Q2.xlsx — 25 risks, uses “Risk Type” taxonomy, numeric 1–5 likelihood & consequence, inherent + residual scores
  • 🏦 SG_Specialty_Clinics_Risk_Register_Q2_2026.xlsx — 20 risks, uses “Category”, Low/Medium/High/Very High ratings, YYYY-MM-DD dates
  • 🏥 JB_Regional_Risk_Register_July2026.xlsx — 18 risks, compact schema, uses “Domain”, RAG only, some missing owners
  • 💎 Wellness_Clinics_Group_Risk_Log_July2026.xlsx — 16 risks, uses “Risk Theme”, likelihood as percentages, financial impact as ranges
  • 📚 Group_Enterprise_Risk_Taxonomy_Reference.xlsx — the target taxonomy (9 enterprise categories) and target reporting schema
Task 1020 min📈 Analyst · Standardize + map + flag exceptions

Consolidate the four subsidiaries into one Group risk register

In copilot.microsoft.com, switch mode to Analyst, attach all 5 files, and paste:

I’ve attached 4 subsidiary risk registers (KL Hospital, SG Specialty Clinics, JB Regional, Wellness Clinics Group) and the Group Enterprise Risk Taxonomy Reference. Each subsidiary uses different column names, different rating scales, and different category taxonomies. Standardize them into one consolidated Group risk register, following the target schema in the taxonomy reference file. For every risk: - Map its local category (Risk Type / Category / Domain / Risk Theme) to one of the 9 enterprise categories in the reference file. Show your confidence for each mapping. - Normalize likelihood and impact into a consistent 1–5 scale. - Compute residual score (likelihood × impact) and residual band (Red ≥15, Amber 8–14, Green ≤7). - Keep the source file name so we have an audit trail. Then flag these exceptions: - Risks above appetite (residual ≥15) - Risks missing an owner - Risks with a target closure date that’s already passed - Categories you couldn’t confidently map (confidence below 80%) — I’ll review those manually - Duplicate risks that appear in more than one subsidiary under different names Give me: (1) the consolidated Group register as a downloadable Excel file with three sheets (Consolidated Register, Exception Summary, Category Mapping Table), (2) an exception summary with counts by exception type and by subsidiary, and (3) a category-mapping table showing how each subsidiary’s taxonomy maps to the Group taxonomy with confidence scores. Apply light formatting on the Consolidated Register sheet: freeze the header row, colour the residual_band column (red / amber / green), and bold the header row.
Getting the Excel file out: Analyst shows results in the chat by default. To get a real .xlsx you can open in Excel, look for the “Download” link that appears below the code output — Analyst generates the file in its sandbox and gives you a link. If you don’t see one, follow up with: “Save that as an .xlsx file I can download.” Analyst will regenerate with the export step included.
Tip: Analyst will show its Python code. If a category mapping looks wrong, ask “show me the mapping rules you used for [category]” and adjust with a follow-up prompt like “treat ‘Data & Privacy’ as Cyber & Information, not as a standalone category.”
Why this matters: This is the annual Group Risk consolidation exercise, done in 20 minutes instead of 2 weeks. Every mapping decision is documented in code, so the Audit Committee can see exactly how “Human Capital” (SG) became “People & Culture” (Group). Defensible, repeatable, auditable.

Tips & PromptsPractical guidance for RM/IA use of M365 Copilot

Tip 1 — Always ground on a specific document All surfaces

Use “Reference this document” or the / command to anchor Copilot to your audit charter, risk register, or regulatory framework. Ungrounded prompts produce general AI answers — not audit-defensible outputs. Every claim in an audit report must be traceable to a source.

Tip 2 — Require a citation for every claim Word · Agent Builder

Add this line to every prompt: “For every finding, recommendation, or regulatory clause, cite the source document name and section in parentheses.” If Copilot cannot cite it, it should not be in the output. Delete uncited claims and replace with [PLACEHOLDER — requires evidence].

Tip 3 — Never paste privileged or sensitive content All surfaces

Do not paste into Copilot: PII (patient names, employee data), whistleblower reports, matters under legal privilege, active regulatory correspondence, or third-party commercially sensitive data. Use sample files only. When in doubt, ask Group Legal before using Copilot on a document.

Tip 4 — Validate outputs against source evidence Excel · Word

Copilot can misread tables, especially merged cells, multi-row headers, or numeric columns formatted as text. After any Excel analysis, manually spot-check 3–5 figures against the raw data. After any Word draft, read every finding paragraph and confirm it matches the referenced source document section — Copilot occasionally paraphrases incorrectly.

Tip 5 — Use Coaching in Outlook for tone-sensitive correspondence Outlook

Audit correspondence (management letters, incident notifications, escalation emails) must strike a precise tone: formal, direct, and independent. Use Coaching by Copilot after drafting — select “More formal” and “More direct”. For responses to management, also select “More concise” to remove hedging language that undermines audit authority.

Tip 6 — Cross-check with a second prompt run Researcher · Word

For high-stakes outputs (audit opinions, regulatory compliance assessments), run the same prompt twice with slightly different framing. Compare the two outputs for consistency. Divergences in findings count, rating, or regulatory interpretation are signals that the source material is ambiguous and needs human review before the report is issued.

Tip 7 — Treat agent knowledge as version-controlled Agent Builder

Whenever the audit charter, risk register, or regulatory framework is updated (e.g. annual charter refresh, risk register quarterly update), republish the agent with the new document version. An agent grounded on a stale charter will give outdated rating-scale guidance. Add a “version last updated” note to the agent description so users know how current it is.

Tip 8 — Use the GCSE framework for every prompt All surfaces
Goal — What do I want? (An audit report draft. A risk heatmap. A 3-bullet escalation summary.) Context — Who is it for? What is the situation? What constraints apply? (Audit Committee. Q3 control testing. IIA IPPF standards apply.) Source — What documents am I grounding this on? (Reference 04 Fabrikam_Internal_Audit_Charter.docx.) Expectations — Format, length, what to include, what NOT to include. Add to every prompt: “Do not invent data, findings, or regulatory clauses. Use [PLACEHOLDER] for missing information.” “Cite the source document and section for every claim.”
